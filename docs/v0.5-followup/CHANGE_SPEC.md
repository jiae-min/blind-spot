# v0.5 이후 설계 변경 명세

## A. 화면 및 공통 정책

1. 사용자가 파일 생성을 요구할 때만 파일 생성. 본 문서는 이번 요청을 받아 만든 것.
2. 상단 **긴급 도움 버튼은 항상 유지**, 하단 긴급전화 목록은 결과·타임라인 뒤로 이동.
3. 하단 섹션명은 **‘긴급 연락처와 도움말’**. 상황별 연락처 아코디언 + 기관별 통화 예시 + 전화 시 전달하면 좋은 핵심 정보(현재 지역/위험 여부/필요한 지원/동반자나 부상자/회신 안전성) + 공식 상담시간 및 비전화 대안 통합.
4. 이용자가 신고를 원치 않거나 증거·서류가 부족한 상태에서 신고/서류를 전제조건처럼 강요하지 않음. 단, 기관의 공식 신청요건이나 법적 예외가 존재하면 정확히 표시.
5. **단기**는 지금~7일 이내 해결해야 할 사안(의식주/긴급 비용 부족 예외 포함), **장기**는 7일 초과에 걸쳐 달성할 지속적 성과. ‘7일 안에 지원 완료’를 보장해서는 안 됨.
6. ‘어떤 도움을 받고 싶으신가요?’는 대분류별 다중 확장 아코디언·복수 선택. 선택한 **항목 바로 아래** 관련 제도·기관 정보를 보여주고 후속 응답에 맞춰 조건·추천 순서를 갱신.
7. 결과 내용은 확인된 객관적 사실만: 기관명·지원 내용·대상·신청 경로·비용/운영시간(검증된 경우)·필요서류·공식출처·최종 확인일. 불확실 항목은 ‘확인 필요’.
8. 타임라인은 선택된 행동을 통합해 우선순위별·병행 가능하게 제시. 장기 지원 상세에서는 개별 자격·증빙 체크리스트를 선택적으로 열람.

## B. 4개 케이스별 질문 전략

- **가정폭력 단기:** 선택적 위험 확인 1문항. 이후 지원 찾기 아코디언과 동거/분리 준비/분리 후 선택적 바로가기. 응급 위치는 시·도 → 시·군·구를 **선택적으로 확인**.
- **성폭력 단기:** 선택적 긴급성 확인 1문항(의료, 위협, 불법촬영·유포 등). 선택적 현재 지역. 긴급의료·증거보전 상담 및 디지털 피해의 시급성을 고려하되 상세 피해 진술 강요 금지.
- **가족돌봄 단기:** 돌봄 공백/응급상황 1문항, 긴급 돌봄·의료·식사·비용 안내. 지역별 기관이 필요할 때만 위치 선택.
- **생계·교육 단기:** 식사·숙소·의료비·공과금·임박한 학비 등 긴급성 1문항, 이후 지원 탐색. 지역이 필요할 때만 선택.
- **가정폭력 장기:** `지원 목표 → 생활 상황 → 지역 → 나이 → 가해자 관계 → 현재 겪는 어려움 → 신고 의사` 총 7문항(무응답 허용).
- **성폭력 장기:** `지원 목표 → 현재 이용 지원 → 지속 안전 문제 → 지역 → 나이 → 현재 어려움 → 신고 의사` 총 7문항.
- **가족돌봄 장기:** `지원 목표 → 돌봄 대상 관계 → 필요한 돌봄 → 현재 이용 중 서비스 → 지역 → 본인 나이 → 돌봄 대상 연령대 → 현재 어려움` 총 8문항.
- **생계·교육 장기:** `지원 목표 → 활동상태 → 지역 → 나이 → 현재 어려움` 기본 5문항; 소득·복지, 주거·가구는 지원 내용상 필요할 때 추가.
- 어려움 질문의 최종 제목은 **‘현재 겪고 있는 어려움이 있나요?’**. ‘괜찮아요’는 다른 항목과 배타적으로 선택됨.

## C. 설문 및 추천 엔진

1. 첫 지원 목적 선택 즉시 후보 제도 요약 표시. 마지막 문항까지 모두 답변할 때까지 화면을 막지 않음.
2. 지원 목적은 **관계있는 후보 목록**, 지역·나이·대상·관계는 **공식 조건 검토**, 서류/연락/신고 의사는 **실행 가능한 경로/순서 조정**. 모두 같은 강제 삭제 필터로 사용하지 않음.
3. 입력이 없거나 요건이 미확인일 때 후보를 삭제하지 않고 ‘추가 확인 필요’ 상태 유지.
4. 소득·재산·정확한 주소·구체적 피해 진술·진단명 등은 모든 사람에게 묻지 않고 필요한 지원 상세에서 선택적으로 확인.
5. 공개 제도 데이터는 제도 ID 기반으로 재사용, 작은 인덱스와 상세 자료를 분리할 수 있으나 MVP에서 과도한 요청 분할은 피함. 질문 순서만으로 다운로드 용량이 줄어드는 것은 아님.
6. 저장·분석·URL에 폭력 피해·연락 의사 등 민감정보를 남기지 않는 것을 기본 정책으로 고려.

## D. 센터 연결 구조

1. 폭력 대응 긴급 위치는 **현재 있는 시·도/시·군·구**. 주민등록 주소가 아님. GPS·실시간 직선거리 계산·외부 경로 API 사용하지 않음.
2. 서울 선택 시 **서울 센터만 기본 조회**, 일부 서울 접경 구에만 미리 연결한 **경기 센터를 추가 후보**로 표시.
3. 경기 선택 시 **경기 센터만 기본 조회**. 서울 센터는 자동 추가하지 않음.
4. 지역 키는 `서울특별시/서울특별시/중랑구`, `경기도/성남시/분당구`, `경기도/구리시`처럼 시·구 세트를 유지.
5. 아동형 센터는 별도 유형·대상 조건을 적용. 가까운 아동형 센터가 성인의 일반 응급센터를 대체하지 않도록 함.
6. 센터별 연결표는 정적 데이터. 입력 지역에 대응하는 기본 센터 ID와 예외 센터 ID로 기관 상세에 연결. 사용자에게 ‘최단거리’라 단정하지 않음.
7. 구 안에 센터가 없는 서울 중랑구 등의 경우에도 **실제 있는 근처 경기 센터를 검증하지 않았다면 억지로 추가하지 않음**. 중랑구의 기본은 서울북부.

## E. 이후 최종 QA 우선순위

- 빠른 안전 도움 접근성(상단 버튼, 질문 건너뛰기, 응급시 설문 지연 금지)
- 신고 의사 vs 상담 연락 의사 구분 및 충돌 규칙 확인(별도 문서 참조)
- 센터 주소/운영시간/연락처 공식 재확인, 실수로 잘못된 장소/번호 보여주지 않기
- 모든 지역 매핑에 적합한 센터(긴급형/아동형) 표기 여부
- 서울 접경 예외 후보의 교통 접근성 검증
- 모바일에서 처음부터 모든 데이터를 다운로드하지 않는지 측정
